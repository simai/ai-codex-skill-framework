# SIMAI Framework visual product platform mapping

For every interface request, identify the exact Framework/project version and build a
source-backed inventory in this order: page recipe, block, Smart Component,
ordinary component, primitive, utility, and semantic token. Reuse a fitting
entry; extend a compatible entry when its public contract permits it; create a
new entry only after recording the unmet need, inspected inventory, `no_fit`
reason, owner, compatibility boundary, tests, docs, and promotion route.

A SIMAI Framework target cannot be delivered as unrelated standalone HTML. Visual Grammar
values map to existing semantic tokens. Literal values and new tokens require a
recorded `no_fit`. Component and block creation must retain states,
accessibility, responsive behaviour, browser evidence, and registry lineage.
